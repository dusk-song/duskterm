## 1. 计划目标与执行规则

把“能够对话”逐步扩展为“能够结合环境分析、查询、执行并验证”，每轮交付一个独立可用的闭环。

本计划为需求拆解和实施顺序，不是开发完成记录，也不代表用户已批准所有建议默认值或未来写操作。开始每轮前核对实际代码、说明拟实施范围与验证方式，按现有确认规则推进；已确认范围内的连续修改不重复申请确认。

执行规则：

1. 先稳定现有聊天，再增加环境信息；先读取，再执行；执行先限定单目标；文本上下文允许用户从不同活动终端直接追加。
2. 每轮完成数据生命周期、失败处理和最低必要验证，避免只交付正常路径界面。
3. 优先复用 Rig、现有 Session Supervisor、SSH/SFTP 与渲染组件。
4. 不为后续阶段提前建设完整框架；仅预留已知需要的关联标识和边界。
5. 计划中的代码位置是影响范围，实施前再核对调用方，不要求按计划机械新增同名模块。
6. 当前原生窗口或真实服务验证受阻时，记录替代证据与局限，保留未通过的发布门槛。

本计划暂不承诺日期或人天。M0 的真实环境问题、M3 的运行时兼容性、M4 的远程取消语义是主要不确定项；对应验证完成后再按实际投入排期。

## 3. 统一验收方式

### 3.1 验收层次

| 层次 | 主要目的 | 适用方式 |
|---|---|---|
| 契约/局部 | 目标、授权、预算、迁移等确定性规则 | 受影响模块的已有测试或小型有价值回归 |
| IPC 与状态 | 竞态、取消、事件顺序、草稿保护 | 模拟延迟/乱序及真实 Store/后端入口 |
| 真实 SSH/SFTP | 范围、编码、退出码、断线与进程状态 | 用户提供或明确授权的非生产测试环境 |
| 真实模型 | 两类现有协议、工具调用和用量 | 明确选定的测试服务，记录真实调用产生用量 |
| 原生交互 | 流式、焦点、滚动、停止与大输出 | Tauri 原生 WebView；浏览器结果仅为补充 |

验证优先局部，不默认全量 clean 或构建无关工程。Rust、前端及数据库发生相应变化时，运行受影响检查和构建；仅文档更新时检查链接、编号、一致性和 diff。

### 3.2 每轮交付记录

- 实际完成的需求与关联文件。
- 已执行验证、环境、结果，以及不能覆盖的范围。
- 数据格式变化、升级备份及回退限制。
- 未完成项、可复现问题和下一步。
- 功能是否可发布与是否可继续下一轮分别判断。

不要求额外建立独立总结文件，沿用现有 Task 记录实际进展，正式需求文档保持当前有效内容。

## 4. M0：现有聊天基础验收

### 4.1 目标

承接现有基础加固的未完成验收，确认流式、取消、摘要与数据升级在实际产品环境可用。已经通过且未受改动影响的本地检查不重复执行。

### 4.2 工作拆解

| 编号 | 工作 | 涉及范围 | 交付/验收 |
|---|---|---|---|
| M0-01 | 核对基线、工作区和既有验证记录 | Task、Git、配置 | 明确已通过与未覆盖项目，不把浏览器验证等同于原生验证 |
| M0-02 | 选定两类协议代表服务及测试模型 | 模型服务配置 | 确认窗口/输出/思考参数可用；不为了测试静默改写用户 256K 配置 |
| M0-03 | 原生窗口验证正文、思考和长代码流 | AI 面板、渲染 | 生成完成前内容可见，思考开合符合当前规则 |
| M0-04 | 验证取消、重生成、切换聊天与面板 | Store、运行生命周期 | 无串流、重复发送、草稿丢失及迟到事件污染 |
| M0-05 | 验证摘要、旧库升级与恢复说明 | runtime、storage | 使用副本/临时数据；失败不破坏原历史；不直接操作唯一用户数据库 |
| M0-06 | 按发布平台完成抽验并分级问题 | Tauri、平台凭据与存储 | 列出阻断发布问题与非阻断问题；不把无环境的平台标记通过 |

### 4.3 出口标准

- 目标平台关键路径无未解决的数据丢失、目标错乱、无法停止或持续阻塞问题。
- 尚未支持的平台或服务明确记录范围。
- 若需修复，按最小范围独立修复并验证；不借机扩大为模型配置重构。

## 5. M1：终端选区纯文本链路

### 5.1 用户闭环

打开 SSH 或本地 PowerShell/CMD 终端 → 选中报错 → 文本插入智能助手草稿 → 在现有输入框编辑并补充问题 → 发送 → 流式回答 → 历史可回看/重新生成。

不新增附件卡片、附件对象、文件/图片入口或附件表，不依赖 Agent runtime。来源说明是可编辑文字，后续执行权限由后端单独校验。

### 5.2 工作拆解

| 编号 | 工作 | 实现要点/影响范围 | 完成标准 |
|---|---|---|---|
| M1-01 | 定义文本格式与最小来源关联 | AI/SSH 状态、现有正文契约 | 目标、终端类型、Channel、时间/范围简短可读，不新建附件模型 |
| M1-02 | 来源和切换规则 | SSH Store、AI 草稿 | 读取当前活动终端，直接追加，不改写旧来源、不把正文当权限 |
| M1-03 | 选区转文本入口 | `Terminal.vue`、菜单/快捷键 | 兼容智能复制，不自动发送、不回写终端 |
| M1-04 | 草稿插入和焦点 | `AiPanel.vue`、Store | 保留已有文字；合理分隔；可直接编辑删除；不抢用户后续焦点 |
| M1-05 | 清理与长度限制 | 文本工具、后端预检 | 保留缩进换行；超限提示；不静默修改实际发送正文 |
| M1-06 | 文本进入请求与预算 | `ai/mod.rs`、`runtime.rs`、`config.rs` | 发送使用最终草稿；系统提示与文本能力一致；无隐藏采集 |
| M1-07 | 草稿、历史和兼容 | 现有 storage/消息类型 | 复用正文存储，必要元数据兼容扩展，不为附件升级数据库 |
| M1-08 | 摘要、删除和重生成 | 历史组装、摘要失效 | 原正文重生成，不重新抓取终端；旧文本保留历史时效 |
| M1-09 | 局部回归、原生交互与说明 | 受影响前后端、README | 用例通过，说明只描述已实现的文本入口 |

### 5.3 验收用例

| 编号 | 操作/条件 | 预期 |
|---|---|---|
| AC1-01 | 导入多行报错 | 草稿含可读来源，换行/缩进正确，无附件卡片 |
| AC1-02 | 已有文字草稿，再导入选区 | 原文字保留，不自动请求模型 |
| AC1-03 | 空选区或仅有空白 | 不插入空内容；普通文字发送规则保持有效 |
| AC1-04 | A 分屏导入后切到 B | 文本和来源不被 B 覆盖，不从正文取得 B 的执行权限 |
| AC1-05 | 导入过程中切聊天或继续输入 | 迟到操作不插入其他聊天、不覆盖新草稿 |
| AC1-06 | 编辑文本/来源，切换模型服务 | 发送最终编辑正文，数据去向告知覆盖当前文本和历史 |
| AC1-07 | 超长选区或模型预算不足 | 说明原因，保留草稿，不静默裁切或产生半份问题 |
| AC1-08 | 重启、回看和重新生成 | 现有正文存储可恢复，不重新读取当前终端 |
| AC1-09 | 删除含环境文本的消息 | 沿用消息删除和摘要失效，无独立附件清理负担 |
| AC1-10 | 无 SSH、旧历史、未知模型 | 普通聊天可用，既有预算校验保持生效 |
| AC1-11 | 来源终端断开后分析正文 | 可分析历史文本，不产生执行权限 |
| AC1-12 | ANSI、宽字符、敏感片段及编辑过的来源 | 清理后文字可见；不执行控制序列、不把来源文字视为可信认证 |
| AC1-13 | 本地 PowerShell/CMD 的选区和右键入口 | 与 SSH 共用草稿链路，标注本地及 Shell 配置名称，不采集环境变量或写入终端 |
| AC1-14 | 本地与 SSH、两个本地实例之间切换来源 | 直接追加当前活动终端文本到原草稿，不确认或新开对话，来源各自保留 |

### 5.4 出口与回退

- CTX-01、CTX-02、CTX-03、CTX-06 对应文本范围通过。
- 真实模型与原生窗口至少完成一次选区 → 文本草稿 → 回答闭环。
- 保持现有存储和请求结构为主，不引入独立附件存储或多模态 API。
- 停用导入入口后，已存正文仍能按普通聊天读取和分析，不再后台采集环境文本。

## 6. M2：近期终端输出转文本

### 6.1 用户闭环

助手输入框最左侧菜单选择范围 → 读取当前活动终端/聚焦分屏 → 有界采集/清理 → 直接追加到当前草稿 → 编辑后发送。文件附加、编辑器片段附加和图片不在本轮范围内。

### 6.2 工作拆解

| 编号 | 工作 | 实现要点/影响范围 | 完成标准 |
|---|---|---|---|
| M2-01 | 定义输出范围 | 终端 Buffer 适配 | 可见区域与最近 N 行语义明确，受行数及字节上限约束 |
| M2-02 | 有界采集与重建 | `Terminal.vue`、局部函数 | 不先复制全部历史，处理折行/宽字符/备用屏幕 |
| M2-03 | 统一入口、范围和时效 | AiPanel、公共菜单、草稿文本 | 输入区左侧带入、右侧模型及发送；显示时间/范围/截断，无浮动控件 |
| M2-04 | 重采集与草稿保护 | AI/终端状态 | 生成新文本，保留既有用户编辑，不改已发送消息 |
| M2-05 | 取消及乱序处理 | 面板/终端读者注册、采集生命周期 | 取消/切换/编辑后迟到结果不写入；当前活动分屏定位准确 |
| M2-06 | 性能与原生验收 | 长历史样本、实际 WebView | 输入、滚动、切换保持可操作，正文存储/预算复用 M1 |

### 6.3 验收用例

| 编号 | 操作/条件 | 预期 |
|---|---|---|
| AC2-01 | 大历史中获取最近 N 行 | 只处理限定范围，界面保持可操作 |
| AC2-02 | 长行折叠、中文、清屏 | 顺序合理，范围和缺失信息明确 |
| AC2-03 | Vim/top 等备用屏幕 | 标为当前画面，不声称完整命令历史 |
| AC2-04 | 两次采集间输出变化 | 生成新文本，旧消息不变，用户草稿不被覆盖 |
| AC2-05 | 采集超限或正文预算不足 | 导入前提示范围限制，发送前预检最终正文 |
| AC2-06 | 采集中取消/切换聊天和目标 | 迟到内容不进入新草稿，无隐藏附件或文件读取 |

### 6.4 出口与回退

- CTX-04 的文本采集范围通过，CTX-05 继续延期。
- M1 的编辑、预算、存储、摘要和重生成链路均可复用。
- 停用输出采集不影响选区导入、普通聊天或 SFTP。

## 7. M3：Rig 受限查询工具

### 7.1 用户闭环

用户选择当前 SSH 目标、检查实际路径并启用下一次提问的只读范围 → 发送问题 → Rig 决定是否查询 → 每次调用经后端校验再读取 → 展示文本结果和真实执行状态 → 模型结合结果回答。检查或取消范围不会调用模型。

首批只接结构化读取，结果为文本/必要元数据，不上传或附加文件。当前不依赖附件系统；已避开会收集整个目录的高层 read_dir，改用既有 SFTP 的原始分页/有界读取通道。暂不暴露任意 Shell。工具调用时已需要最小 Agent 循环，M5 在此基础上增加任务管理。

### 7.2 工作拆解

| 编号 | 工作 | 实现要点/影响范围 | 完成标准 |
|---|---|---|---|
| M3-01 | Rig 运行时兼容性验证 | `Cargo.toml`、锁定版本源码、现有 provider | 最小工具调用、流式、错误、停止与等待确认可实现；不默认整体升级 |
| M3-02 | 工具能力元数据与降级 | 配置/探测/有效能力解析、设置局部 UI | 能区分支持、不支持和未知；未知不误标为已验证 |
| M3-03 | 运行与目标绑定 | AI runtime、Session Supervisor | 后端绑定运行连接及代次，不接受模型指定任意目标 |
| M3-04 | 读取授权模型 | 后端授权状态、前端确认卡片 | 范围、有效期、目标和操作类别明确；拒绝/取消可闭环 |
| M3-05 | 路径与参数校验 | 共享 SFTP 路径逻辑、工具入口 | `..`、符号链接、分页、编码与字节限制在后端生效 |
| M3-06 | 首批 Tool 实现 | 目录、文本片段、属性工具 | 复用 Session/SFTP 服务；错误类型明确；输出有界 |
| M3-07 | 工具事件和状态卡片 | `AiEvent` 的兼容扩展、Store、消息展示 | 运行/调用 ID 与序号关联，迟到/重复事件可识别 |
| M3-08 | 工具结果进入上下文和预算 | Rig 适配、runtime、摘要 | 保持真实调用/结果协议，调用结果成对；预算不足能中止并解释 |
| M3-09 | 记录、删除和诊断日志 | storage、call_log | 工具结果可回看；日志无正文；未授权/拒绝操作不伪造结果 |
| M3-10 | 模型、SSH/SFTP 与授权联调 | 两协议代表服务、原生 UI | 正常路径、越界、拒绝、断线和取消通过 |

### 7.3 兼容性验证必须回答的问题

1. 当前动态多服务模型如何接入运行时，是否保留原代理、超时和凭据获取？
2. 两类协议如何返回工具参数、并行请求与流事件？服务不支持时怎样降级？
3. 等待用户批准时，如何暂停在真正的执行入口之前，而非工具已经启动后再展示确认？
4. 取消如何传递到模型、授权等待和 SFTP 读取？
5. 工具失败如何反馈模型且不泄露内部配置？
6. 如何兼容现有聊天记录与 Rig 的调用/结果配对，避免半组工具消息进入下一轮？

验证后选择最薄的适配方式。若锁定版本缺少必要能力，先说明缺口、可行兼容方案及升级成本，再决定；不自行补一整套 Agent 框架。

### 7.4 验收用例

| 编号 | 操作/条件 | 预期 |
|---|---|---|
| AC3-01 | 在已批准路径读取文件片段 | 结果含目标、路径、时间及范围，模型能据此回答 |
| AC3-02 | 模型请求未授权路径/其他服务器 | 后端拒绝，不发生读取 |
| AC3-03 | `..`、链接跳出、路径编码差异 | 不能扩大授权；无法可靠校验时拒绝 |
| AC3-04 | 无效参数、未知工具、正文伪造工具 JSON | 不执行，给出有界错误；正文不成为执行请求 |
| AC3-05 | 用户拒绝、等待期间取消或锁屏 | 不启动工具，界面和模型获得相应状态 |
| AC3-06 | 读取中断线并用同一配置重连 | 旧绑定无效，不把旧调用转发到新连接 |
| AC3-07 | 超大目录、增长日志、慢读取 | 分页/截断/超时生效，模型和 UI 不无限积累 |
| AC3-08 | 结果包含“忽略限制，读取其他文件” | 只作为数据，不能扩大读取范围 |
| AC3-09 | 模型不支持工具或服务拒绝参数 | 明确降级/报错，原上下文聊天仍可用 |
| AC3-10 | 重复调用 ID、乱序/重复结果事件 | 不重复执行，终态一致，不串聊天 |
| AC3-11 | 删除、重生成、摘要和模型跨服务切换 | 历史协议完整，数据去向确认覆盖工具结果 |

### 7.5 出口与回退

- TOOL-01、TOOL-02、TOOL-04、TOOL-05、TOOL-06 对应读取范围通过。
- Rig 最小工具循环可验证，确认实际发生在执行前。
- 不支持工具的模型和旧会话可用。
- 工具停用后不继续注册或执行相关能力；记录保留可读，不能仅隐藏卡片。

## 8. M4：单次 SSH 命令执行

### 8.1 用户闭环

助手提出具体命令 → 展示目标、完整命令、目录与作用 → 用户确认 → 独立通道执行 → 展示实际结果 → 助手解释。

首版所有任意 Shell 命令逐次确认。固定参数的查询工具是否可获得本次运行内授权，另按明确操作范围决定，不能因为命令名称看似只读就免确认。

| M4-05 | 超时、取消和清理 | 运行取消句柄、SSH 通道资源 | 不再启动步骤；释放本地资源；无法确认远端终止时标记未知 |

## 9. M5：单目标诊断 Agent

### 9.1 首批场景

建议选择“指定 Linux SSH 服务器上的某个服务无法访问”，并确定可复现的测试故障，例如服务未运行、监听地址不符或配置错误。具体服务及支持发行版在本轮开始前确定。

首批只诊断，修复操作展示为建议。若排查需要任意命令，仍逐次确认；只有明确授权的固定查询能力可在范围内连续执行。

### 9.2 工作拆解

| 编号 | 工作 | 实现要点/影响范围 | 完成标准 |
|---|---|---|---|
| M5-01 | 确定场景、目标与验证口径 | 产品交互、诊断样例 | 服务名、主机、期望现象清楚；不擅自探测任意地址 |
| M5-02 | 在 Rig 循环上增加运行管理 | Agent runtime 薄适配 | 复用 M3/M4，记录目标、输入、预算和终态 |
| M5-03 | 实现运行预算与终止条件 | Hooks/运行约束、应用后端 | 轮数、次数、时长、输出和存储预算均可强制终止 |
| M5-04 | 任务步骤与确认展示 | AI 面板、步骤卡片 | 展示实际工具进度；思考区不作为任务执行记录 |
| M5-05 | 证据、结论和验证结果 | 工具结果关联、模型最终输出 | 区分事实、推断、未知；结论可回看所依据结果 |
| M5-06 | 中断、重启和失败收尾 | 运行持久化、恢复逻辑 | 保留已有发现；不自动恢复授权或重放操作 |
| M5-07 | 用量和性能统计 | 用量聚合、元数据日志 | 汇总模型调用与摘要，不漏记/重复；估算与服务实际值区分 |
| M5-08 | 场景回归与发布验收 | 故障样例、真实模型/SSH/WebView | 多种原因下不虚报修复，权限和预算始终有效 |

### 9.3 建议状态与转换

运行状态：待启动 → 运行中 ↔ 等待确认 → 已完成 / 失败 / 已停止 / 已中断。

“预算耗尽”和“证据不足”是收尾原因；任务“已完成”仅表示本轮诊断结束，必须另列问题是否解决。远程操作结果未知是步骤结果，不能被任务终态覆盖。

- 等待确认时停止/拒绝：不执行该步骤，按原因结束或继续获准范围内分析。
- 达到预算：不启动下一模型调用或工具，展示已有发现和未完成项。
- 工具失败：依据错误判断是否还有获准的替代诊断路径；不无限重试。
- 用户切换聊天或关闭面板：运行绑定不变，显示现有运行标记；不自动取消或改绑目标。
- 用户切换模型：只影响新运行；当前任务保持原模型服务。
- 应用重启：恢复记录为已中断/待核实，不直接恢复执行。

| AC5-05 | 运行中切聊天、切终端、切模型 | 任务目标和模型不变，界面不串流 |

## 11. 候选默认限制与预算

以下数值用于实施评估和验证设计；M1 的 64 KiB 选区、M2 的 200/500 显示行和 64 KiB 输出快照、M3 的只读预算已实现，现有正文限制保持，M4 命令 30 秒/256 KiB 已生效，M5 候选值尚未生效。它们是应用侧的保护上限，不能替代模型窗口和服务限制；实施时结合真实样本调整并记录最终值。首版优先使用集中常量，不把所有阈值都增加成用户高级设置。

| 对象 | 候选默认值 | 达到限制时的行为 | 最迟确定 |
|---|---|---|---|
| 单次带入的选区文本 | 64 KiB UTF-8 | 导入前提示选择更小范围；最终正文仍受输入预算约束 | M1 |

| 单次工具读取文本 | 默认 8 KiB、最多 16 KiB UTF-8 正文；本次结果总量 64 KiB | 返回范围/截断；不生成文件附件 | M3 |
| SFTP 列目录 | 默认 50、每页最多 100 条，偏移最多 1000 | 返回分页状态，不自动遍历所有页 | M3 |
| 单次读取超时 | 10 秒 | 分类为超时，可由用户决定重试 | M3 |

## 13. 数据升级、发布与回退要求

1. **先定契约，再定存储。** M1 复用现有草稿和用户消息正文，仅在必要时兼容扩展来源元数据；不设计附件表和独立文件存储。M3/M5 按实际需求增加工具/运行记录。
2. **持久化仍后台执行。** 不因增加环境文本和步骤回到高频重写整份历史；工具输出也不按每个字节落盘。
3. **升级先有一致性备份。** SQLite WAL 情况下沿用一致性备份原则；备份失败不推进不兼容迁移。
4. **回退限制写清楚。** 旧版能否读取新版数据需要实际验证；恢复升级前备份会失去之后新增内容，不能称为无损降级。
5. **程序回退与远程状态分开。** 回退安装包不撤销已经执行的命令或文件修改；必须按实际服务器状态核实。
6. **停止能力在后端生效。** 工具或 Agent 暂停发布时，不能只隐藏按钮而继续注册工具或接收执行。
7. **重启不重放操作。** 待确认、运行中及未知结果恢复为可审阅状态，授权需重新取得。
8. **按支持范围发布。** 原生窗口、真实模型和真实 SSH 的验收没有完成时，不把对应阶段标为完整可用。
