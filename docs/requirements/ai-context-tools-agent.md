## 1. 背景与目标

DuskTerm 已具备模型服务配置、流式聊天、本地历史、多版本回答和长对话摘要。普通聊天只使用用户输入和有效聊天历史；M1/M2 支持用户带入终端文本，M3 支持为单次提问启用 SSH 只读范围。M4 可在逐条确认后通过独立 SSH 通道执行 POSIX 命令；不操作交互终端。

文本上下文同时覆盖 SSH 与 DuskTerm 集成的本地终端（PowerShell、CMD）；工具与诊断首批仍围绕 SSH 运维场景演进：从理解用户问题，发展到理解问题发生的环境，按需获取证据，最终在明确授权下完成并验证任务。

能力演进为：

`AI Chat → Context → Tools → Agent`

这四层是可组合的能力，不要求用户在四个独立产品中切换。无 SSH 连接时继续支持普通聊天；附加上下文和工具权限后，助手获得对应能力。

### 1.1 产品目标

1. 减少用户在终端和对话框之间反复复制粘贴，先贯通纯文本输入、环境、工具结果与回答。
2. 让回答带有明确环境依据，区分观察事实、推断、建议和已经执行的操作。
3. 复用现有 SSH/SFTP 与 Rig 能力，避免建设第二套连接管理或 Agent 框架。
4. 让操作目标、数据发送范围、执行状态和验证结果始终可见。
5. 保持终端输入、流式展示、切换会话及取消操作的流畅性。

### 1.2 首个产品闭环

用户选中终端报错 → 以文本插入智能助手草稿 → 编辑并补充问题 → 发送 → 助手结合该段文本回答。

第一轮到此闭环即可交付，不以实现命令执行或完整 Agent 为前提。

后续闭环：带入报错文本 → 查询状态和日志 → 给出原因与证据 → 用户确认必要操作 → 执行 → 验证目标是否达成。

## 2. 当前基础与实际缺口

以下为基线代码观察，不代表后续能力已经实现。

| 领域 | 当前可复用能力 | 缺口及注意事项 |
|---|---|---|
| 对话 | 服务/模型配置、取消、事件序号、历史版本和摘要 | 已带入的来源说明随用户正文保存；尚无工具调用/结果及任务记录 |
| 终端 | xterm 文本选区、右键操作、独立分屏和 Shell Channel | 需要上下文采集入口、范围限制和来源记录 |
| 当前目录 | 从终端标题推断路径，供界面及 SFTP 跟随使用 | 属于启发式观察；可能缺失、过期或错误，不能直接作为执行目录 |
| 连接管理 | Session Supervisor、SSH 生命周期和共享连接 | 需要可校验的目标绑定、连接代次以及工具执行接口 |
| 文件 | SFTP 列目录、属性、文本打开/保存和并发修改检查等 | AI 读取前需有范围、字节上限、编码处理及数据发送确认 |
| 执行 | 交互式终端输入和 Shell Channel 管理 | 尚无 AI 使用的、按单次命令隔离的标准执行结果契约 |
| Rig | `rig-core`、`rig-memory`、`rig-reqwest` 固定为 0.46.0 | 当前 `rig` 是 `rig-core` 的别名，未接入 Agent 运行时 |
| 验证 | 已有本地模拟与独立浏览器验证记录 | 真实模型服务、Tauri 原生窗口和多平台仍有待验收项 |

## 3. 场景与范围

### 3.1 主要场景

| 场景 | 用户诉求 | 产品行为 |
|---|---|---|
| 报错解释 | “这段启动报错是什么原因？” | 选区以文本写入草稿，带来源说明，结合内容回答 |
| 日志与配置分析 | “这份配置与日志是否对应？” | 当前手动粘贴文本，后续可在授权范围内用工具读取文本；文件附加入口延期 |
| 服务诊断 | “这台服务器为什么访问不了？” | 在指定目标内按需查询，列出证据、结论和不确定项 |
| 辅助执行 | “帮我执行这条排查命令” | 展示执行目标与完整命令，确认后执行并展示结果 |
| 修复与验证 | “修改配置并确认服务恢复” | 后续阶段展示差异、冲突检查、操作确认及验证结果 |

### 3.2 范围分层

| 能力 | 本需求中的定位 |
|---|---|
| 普通聊天 | 保留，作为无环境或不需要操作时的入口 |
| SSH 与本地终端（PowerShell、CMD）的选区及文本快照 | 首批上下文能力，共用文本链路 |
| 文件/编辑器片段附加入口、通用附件及图片 | 后续备选，不是本轮或工具阶段的前置条件 |
| 受限读取工具 | 工具阶段优先交付 |
| 单次非交互式 SSH 命令 | 经确认后逐步开放 |
| 单目标诊断 Agent | 第一种 Agent 产品形态 |
| 配置写入、服务重启等 | 单独的后续可选阶段，需先确认具体操作清单 |
| 本地终端工具执行 | 后续独立评估，当前仅支持用户主动带入文字 |
| Telnet、串口的环境采集及执行 | 本阶段不默认开放，保持手动聊天粘贴可用 |
| 跨服务器联动、多 Agent、定时无人值守 | 暂不纳入 |
| MCP 管理、向量库、自动全盘索引、知识库 RAG | 暂不作为前置条件，后续按场景独立评估 |

## 4. 需求原则

### 4.1 能力与权限匹配

模型只能使用本次运行实际开放的上下文和工具。系统提示随能力变化，禁止出现“工具已可用但仍声明不能读取”，或“没有工具却声称已执行”的矛盾。

SSH 登录权限不等于向模型发送远程数据的授权。用户应能理解读取范围、发送目标及是否会产生模型用量。

### 4.2 以结构化证据为基础

当前环境文本直接进入草稿和用户消息正文，不建设独立附件对象、附件表或卡片。正文带简短来源说明；必要的会话绑定保留在请求/运行元数据中。后续工具调用、结果与任务状态按真实协议独立关联，不能退化成无法追溯的普通文本。

### 4.3 复用与最小新增

优先使用 Rig 的模型协议、工具定义、Agent 循环和 Hooks。DuskTerm 提供环境采集、目标校验、授权执行和产品交互。现有 SSH/SFTP 继续负责连接、认证及文件操作。

### 4.4 按需采集

不持续向模型传输整个终端缓冲区，不预先扫描整台服务器。首批采用用户主动带入草稿的文本快照，后续由受限工具补充必要信息。

## 5. Context 功能需求

### CTX-01：终端选区转文本（P0）

- 当前阶段只贯通文本链路，不实现附件对象、附件卡片、文件上传、拖拽文件、图片粘贴或视觉模型接入。
- 支持把当前 SSH 或本地终端选区以普通文本插入智能助手草稿；通过助手面板的“带入终端输出 → 当前选区”或终端右键入口，兼容现有右键“智能复制”行为。
- 在输入框中带简短来源说明，例如目标、终端、采集时间及文本范围；不生成独立附件区域。
- 打开面板并合理定位输入框，不自动发送、不向终端回写内容。保留已有草稿，插入位置/分隔方式在实施前确定。
- 用户可以像普通文字一样编辑、删改来源说明和正文；文本内的目标名称不构成执行授权。
- 空选区不插入，超长选区先提示缩小范围；多分屏按实际采集的终端确定来源。
- 异步打开/保存不覆盖用户后续输入，不把 A 聊天的文本插入到 B 聊天。

### CTX-02：输入编辑与实际发送一致（P0）

- 直接复用现有输入框进行查看、编辑和发送，不建设单独的附件预览、移除、数量管理和修订流程。
- 选区导入时清理无显示意义的控制序列，保留换行、缩进与代码结构；清理后文本在草稿中可见。
- 最终发送以用户点击发送时的草稿正文为准，不在后台额外添加未展示的终端输出或刷新来源内容。
- 凭据等明显敏感片段可以提示用户检查；首版不引入独立附件脱敏编辑器，用户可直接编辑文字。
- 跨模型服务发送的告知覆盖当前正文、有效历史及后续保留的工具结果。
- 文本已被编辑时，来源说明只表示最初采集来源，不能作为内容未经修改的证明。

### CTX-03：目标绑定和来源追踪（P0）

- 选区来源使用实际运行终端标识、连接/终端名称及采集时间生成简短说明；本地终端只带配置的 Shell 名称，SSH 则注明连接类型；必要元数据复用/最小扩展会话状态，不新建附件存储。
- 已插入的草稿文本和已发送消息保持原样，切换标签页、分屏、聊天或模型不自动改写其来源。
- 离线历史文本可以继续分析，不能恢复成可执行目标；手动粘贴或编辑过的文本也不能用于验证服务器身份。
- 用户每次点击带入时取当前活动终端/聚焦分屏，在当前草稿直接追加；不扫描历史来源、不确认跨来源、不强制新开对话。已有文本的来源说明保持原样。后续工具的执行目标独立绑定，不从正文决定。
- 后续工具运行的目标由后端独立绑定和校验，不从可编辑正文解析；连接重建后旧代次绑定及待确认操作失效。
- 密码、私钥、私钥口令、认证 Token 和完整连接配置不得进入来源元数据。
- 当前目录来自终端标题时仅标为观察值，缺失为未知；不能直接作为命令执行目录。

### CTX-04：近期终端输出快照（P1）

- 用户主动选择把当前可见区域或最近有限行输出插入草稿；不持续跟随终端新增内容。
- 记录采集范围、行数、时间和截断状态，允许重新采集。
- 重新采集生成新的草稿文本，不覆盖已发送的历史正文，也不自动刷新待发送文本。
- 处理换行折叠、宽字符、ANSI 清理和备用屏幕；无法取得普通滚动历史时如实提示。
- 大缓冲区采集保持有界；不得先同步复制整个滚动历史再裁切。

### CTX-05：文件附加与图片（延期备选）

本项移出 M1/M2，不属于当前文本链路的验收范围。后续按使用反馈再评估：

- 通用附件卡片、独立预览/移除及附件持久化。
- 文件上传、拖拽文件、从 SFTP 或编辑器直接附加文件/片段。
- 图片选择、粘贴、预览与多模态请求；单独核对模型能力及大小/格式限制。
- 文件附加需区分编辑器未保存内容与真实远端文件，处理大小、编码、版本和链接范围。

延期附件不影响 Tools 阶段提供有界远程文本读取：工具返回文本和必要元数据，按工具协议进入对话，不产生附件，也不依赖附件系统。

### CTX-06：文本预算与会话记忆（P0）

- 输入预算覆盖系统提示、问题、带入的环境文本、有效历史、工具定义/结果和输出预留。
- 继续复用现有有效预算与 Rig 摘要策略；256K 输出上限不代表输入窗口或可粘贴文本长度。
- 当前草稿超出预算时明确提示用户缩减文本或调整配置，不在发送时静默裁切。
- 环境文本直接随用户消息存储，不增加独立附件表、附件版本或附件草稿。
- 旧消息可按现有规则摘要，但保留来源和历史时效，不把旧环境事实写成当前事实。
- 重新生成使用原用户消息正文，不重新采集当前终端；刷新环境后提问属于新消息。
- 删除沿用现有消息/聊天及摘要失效规则；后续工具记录按关联关系清理。
- 第一阶段无需改变模型的图片能力配置或增加多模态协议适配。

## 6. Tools 功能需求

### TOOL-01：工具注册与模型能力（P1）

- 采用与锁定 Rig 版本相容的 Tool 定义和运行时，不自行维护第二套模型工具调用循环。
- 工具名称、参数 Schema、返回结构、错误类型和是否存在副作用明确。
- 仅注册本次运行获准使用的工具；权限不能仅靠提示词约束。
- 工具调用能力按模型/协议/网关验证，缺失能力保留未知；不从模型名称猜测。
- 不支持工具的模型仍可使用 Context 问答，不将正文中的伪造 JSON 或命令识别成真实工具调用。

### TOOL-02：首批受限读取工具（P1）

候选工具如下，名称仅为需求示意，最终以实施设计为准：

| 工具 | 输入范围 | 结果 | 限制 |
|---|---|---|---|
| 列出目录 | 已授权目录、分页参数 | 条目及分页状态 | 禁止隐式递归，限制单页数量 |
| 读取文本片段 | 已授权文件、行/字节范围 | 文本、路径、范围及截断状态 | 有界读取，处理链接、编码和文件变化 |
| 获取文件属性 | 已授权路径 | 类型、大小、修改时间 | 不扩大到其他目录 |
| 查询状态 | 后续确定的固定诊断参数 | 结构化状态及采集时间 | 依赖经过验证的执行适配，不以任意 Shell 冒充只读工具 |

授权至少约束目标、可读路径/范围、有效期和本次运行。原路径与解析后路径均需检查，防止 `..` 和符号链接扩大范围；无法保证范围时拒绝该次读取。

### TOOL-03：单次 SSH 命令执行（P2）

- 先支持非交互式单次命令，复用现有已认证 SSH 连接能力；执行通道独立于用户正在输入的终端。
- 不通过向交互式终端粘贴命令并自动回车实现工具执行。
- 工作目录、环境、执行用户和 Shell 语义明确；不默认继承终端中的 `cd`、alias、临时变量或 sudo 状态。
- 展示完整命令、目标、目录和预期作用，用户确认后执行；首版不开放永久授权任意命令。
- 确认绑定命令/参数、目标连接代次和请求修订。任一变化、断线重连、取消或授权过期均需重新确认。
- 不接收模型提供的任意主机凭据；目标由本次运行绑定，后端再次校验。
- 首版不支持密码输入、交互式 sudo、PTY 程序和后台常驻任务；遇到需要交互时及时结束或报不支持。
- 结果包含 stdout、stderr、可缺失的退出码、开始/结束时间、超时/信号/取消、截断及目标。
- 标准输出与错误输出可分流展示；跨流顺序仅在有可靠依据时表达。
- 通道关闭不等于远程进程及其子进程已终止，无法确认时标记结果未知。

### TOOL-04：授权策略与执行前校验（P1/P2）

| 操作 | 建议初始策略 |
|---|---|
| 用户主动带入环境文本 | 在现有输入框编辑后发送，明确数据范围和模型服务 |
| 已授权范围内的结构化读取 | 首次明确范围，本次运行内可按范围执行 |
| 超出读取范围 | 请求新的具体范围授权 |
| 任意 Shell 命令 | 每次展示完整内容并确认 |
| 文件写入、服务重启等 | 后续明确操作清单后单独开放，每次确认 |

此表是建议默认值，具体交互在对应迭代实施前确认。批准读取不等于批准写入，批准某个命令不等于批准它的变体。

后端执行入口统一校验：运行是否有效 → 目标是否匹配 → 参数是否有效 → 权限是否覆盖 → 预算是否足够 → 是否已取消。确认后的实际执行参数必须与用户所见一致。

现有命令知识库的敏感命令规则可评估复用，但不能把“未命中拦截规则”视为安全或只读证明。

### TOOL-05：执行过程与结果展示（P1）

- 工具步骤以独立卡片呈现名称、目标、参数摘要、状态、耗时和结果；与模型思考区分开展示。
- 至少覆盖等待确认、运行中、成功、失败、已拒绝、已停止及结果未知。
- 用户可查看完整获准执行的命令和实际返回内容；超限结果采用有界预览与明确截断提示。
- 后端事件带运行 ID、工具调用 ID 和序号；重复、迟到事件不会重复执行或污染其他聊天。
- 取消后禁止启动新步骤；已启动步骤显示实际取消结果，不提前承诺成功终止。

### TOOL-06：失败与重试（P1）

- 区分参数错误、无权限、连接失效、执行失败、模型失败、预算耗尽和结果未知。
- 错误供模型分析的部分不包含凭据、内部连接配置或未经授权数据。
- 读取操作的有限重试需验证目标和授权仍有效。
- 有副作用操作遇到超时、断线或进程中断，不自动重试；先检查实际状态，再由用户决定。
- 同一工具调用 ID 的重复派发不能直接触发第二次远程操作；崩溃后不承诺远程副作用恰好执行一次。

## 7. Agent 功能需求

### AGT-01：单目标诊断任务（P2）

- 第一种 Agent 为单台 SSH 服务器的诊断助手，围绕用户明确的问题运行。
- 使用已授权查询工具获取证据、调整下一步，输出结论、证据、不确定项及建议。
- 第一轮诊断 Agent 不自动写文件、不重启服务；修改方案作为建议或待确认操作呈现。
- 工具阶段已经需要 Rig 的最小调用循环；Agent 阶段是在其上增加目标、预算、任务状态与验证，不另建一套循环。
- 不预先展示未经实际执行的“完成步骤”；模型思考文本不作为进度依据。

### AGT-02：任务运行约束（P2）

- 每次任务绑定目标、模型服务、输入快照、授权范围和运行预算。
- 限制模型轮数、工具次数、单工具超时、总时长、输入输出规模与并发量。
- 首版沿用全局单个 AI 运行的限制，普通聊天和 Agent 不争抢成两个无约束任务。
- 停止后不再创建模型调用或工具步骤；已产生的部分内容保留且标记状态。
- 达到预算或无法继续时给出已有发现和未完成项，不把停止解释为问题已解决。
- 模型切换只影响后续新运行；正在运行的任务不隐式更换模型或数据去向。

### AGT-03：结果验证（P2）

- 任务开始时明确可观察目标；无法客观验证时说明只能提供诊断结论。
- 诊断类结果区分“已确认原因”“可能原因”“证据不足”。
- 操作类任务的成功依据是目标验证，例如服务状态和相应访问探测，不能仅以退出码为零判断。
- 验证同样受目标、工具权限和预算约束；本机与远端的网络可达性结论不能混用。
- 首批不开放任意网络探测目标，探测地址/端口需要纳入范围。

### AGT-04：任务记录与重启（P2）

- 保存用户目标、工具步骤、授权决定、结果和最终结论的必要记录。
- 应用重启后能查看历史及中断状态；不默认自动恢复运行、不重放待确认操作。
- 旧的批准记录只用于审阅，不作为重启后继续操作的凭证。
- 优先利用 Rig 可持久化运行状态，但业务记录与远程执行结果仍由 DuskTerm 管理。

### AGT-05：受控修改（后续可选）

- 单独确定首批写操作清单，例如文本配置修改、指定服务重启；不一次开放全部 SSH/SFTP 写能力。
- 文本修改展示差异，保存前校验文件版本；外部变化时中止并重新分析。
- 批准绑定差异、目标和文件版本；内容变化后重新确认。
- 记录备份位置、适用条件及恢复方式；需要的权限或备份能力不足时阻止相关操作。
- 远程执行通常不是事务，不能承诺整项任务自动回滚；恢复本身也可能失败，应独立呈现。
- 即使配置写入已获批，服务重启仍需覆盖该动作的明确授权。

## 8. 数据与上下文模型要求

以下是职责边界，不是已经确定的数据库表或最终字段命名。

| 对象 | 最低信息 | 生命周期 |
|---|---|---|
| 环境文本 | 复用草稿和用户消息正文；简短来源说明、采集时间/范围；必要会话来源元数据 | 文字草稿 → 已发送正文 → 删除 |
| 目标绑定 | 配置标识、运行连接标识及代次、Channel、必要显示信息 | 运行内有效，重连需重新绑定 |
| 工具调用 | 运行/调用标识、名称、参数、目标、授权修订、状态 | 待处理 → 等待批准/执行 → 终态 |
| 工具结果 | 返回数据、错误、退出状态、时间、范围和证据标识 | 有界保存，可回看，不能冒充当前状态 |
| Agent 运行 | 用户目标、模型、预算、步骤关联、最终结论和中断状态 | 创建 → 运行/待确认 → 终态 |

消息正文、模型上下文与诊断日志分开：环境文本复用现有聊天正文存储；日志默认只记必要元数据。不得在通用 IPC 或诊断日志中打印文件正文、凭据或完整模型请求。

新增数据格式需兼容已有聊天、回答版本、草稿和用量记录；需要升级数据库时提供一致性备份、迁移失败处理及明确回退限制。

环境文本沿用现有消息删除规则；后续工具结果的关联清理、保留策略和容量上限须在引入工具结果的迭代中一并实现，不能无限积累。具体默认阈值见迭代计划的候选配置。

## 9. 性能、稳定性与安全边界

### NFR-01：界面与异步

- 采集、清理、预算计算、持久化和工具执行按工作性质调度；网络异步复用，阻塞 I/O 不占用网络执行线程。
- DOM 与终端 UI 留在主线程，重计算按实测拆分，不仅通过增加 async 或动画掩盖阻塞。
- 文本和工具事件合批、有界缓存；终态刷新未显示片段，用户上翻时不强制滚到底部。
- 慢读取、慢磁盘、长输出或模型长时间无响应时，停止与切换仍可操作。
- 性能结论以固定样本、实际 WebView 和基线对比为准，不预先承诺提速比例。

### NFR-02：信息与执行边界

- 终端、文件和工具结果属于待分析数据；其中的“忽略限制”“执行其他命令”等内容不能授予权限。
- 不暴露任意 Tauri invoke、本地文件系统、SSH 凭据或其他会话的工具句柄。
- 工具 Schema 与 Rig 元数据帮助表达能力，不替代后端权限检查。
- 文件路径、命令参数和显示内容按各自语义处理，不把模型输出拼成未经确认的 Shell 操作。
- 锁屏、会话断开、目标失效后，不继续启动新的远程操作；已运行操作的处置策略在工具迭代中明确并验收。

### NFR-03：兼容与降级

- 不支持工具调用的模型降级为普通上下文问答。
- 不可用的 SFTP 或文件权限只影响相关工具，不破坏终端及普通聊天。
- 代理、跳板机、主机密钥确认和现有认证流程继续复用。
- Windows 为当前主要开发验证环境；发布范围涉及 macOS/Linux 时完成对应平台验收，不以独立浏览器代替原生窗口验收。

## 10. Rig 与应用职责

| 能力 | 优先复用 | DuskTerm 负责 |
|---|---|---|
| 模型调用与流 | Rig Core、现有服务适配 | 配置、请求生命周期、数据发送目标 |
| 摘要与记忆 | Rig Memory 与已有集成 | 有效历史、来源、预算和失效管理 |
| 工具协议与调用循环 | 相容的 Rig Tool / Agent 运行时 | 实际工具、授权、目标和执行限制 |
| 运行钩子与状态 | Rig Hooks / AgentRun 等，按锁定版本验证 | 确认交互、持久化映射、停止和恢复规则 |
| 远程连接及文件 | 现有 SSH/SFTP 服务 | 工具适配、有界读取、版本检查 |

接入前验证动态多服务模型、两类现有协议、流式工具事件、暂停等待确认、取消和错误恢复是否满足需求。M3 已固定接入 `rig-agent =0.46.0`，由其处理工具调度、调用/结果配对和流式循环；普通聊天仍复用现有直接 Completion 链路。

优先补充与 0.46.0 相容的 Agent 组件，避免为了单一 API 顺便升级全部依赖。若需要升级，另行评估迁移范围并验证原有聊天和摘要。

官方文档用于能力参考，具体 API 以锁定版本源码为准：[Rig 架构](https://rig.rs/docs/architecture)、[工具](https://rig.rs/docs/concepts/tools)、[Hooks](https://rig.rs/docs/concepts/hooks)。

## 11. 总体验收与实施前待决策项

### 11.1 总体验收

1. 用户能看清模型实际获得的上下文、来源、目标和时间。
2. 切换聊天、分屏、服务器或重连不会让数据与操作串到其他目标。
3. 普通聊天不依赖 SSH，不支持工具的模型仍能完成上下文问答。
4. 所有工具均经过后端校验，未批准、已过期及参数已变化的操作无法执行。
5. 任务状态反映实际运行，停止、失败、未知和成功可区分。
6. 旧历史、草稿、回答版本和用量保持兼容；迁移可恢复，删除无孤立正文。
7. 流式正文与工具结果有界展示，长输出和慢存储不阻塞终端操作。
8. Agent 以证据和目标验证收尾，不把命令执行成功等同于任务完成。

### 11.2 各阶段实施前确定

| 决策 | 最迟确定阶段 | 建议 |
|---|---|---|
| 选区入口与右键冲突处理 | M1 | 保留智能复制，提供独立可达入口；快捷键通过统一配置管理 |
| 单次带入文本长度和输入预算阈值 | M1 | 后端统一强制上限，界面预检；采用计划中的候选值验证 |
| 活动终端与跨来源规则 | M1/M2 | 每次带入读取当前活动终端，直接追加并保留来源；工具运行目标仍独立绑定 |
| 读取授权与有效期 | M3 | 明确路径与本次运行，超范围重新批准 |
| Agent 依赖接入方式 | M3 | 固定兼容版本，先验证最小工具循环与取消/等待确认 |
| 命令 Shell、目录、停止和锁屏策略 | M4 | 非交互式、显式目录、停止后不再启动步骤 |
| 首批诊断场景和支持环境 | M5 | 一个可复现的 Linux SSH 服务故障场景先闭环 |
| 写操作清单及恢复边界 | M6（可选） | 单独确认后实施 |

文档确认、功能实施授权和验收完成是不同状态。当前 M1/M2/M3/M4 已获授权并本地实现，最终验证见配套计划；真实模型、SSH/SFTP 与原生窗口待验收，M5 及以后不视为已实施。

## 17. M3 当前交付（2026-11-06）

本节补充 v0.6 的当前能力；此前 M1/M2 交付段中的“无工具”“数据库 v3”为当时状态。

- 输入区使用公共 IconButton、Dialog、Input、Label、Button 检查并启用单次 SSH 读取范围，明确目标、实际路径、模型服务和有效期；检查范围只解析属性，不读取文件正文或调用模型。切换目标/聚焦分屏、模型/对话、关闭面板、断线、取消及锁定会清除待用范围，迟到检查结果会撤销。
- 后端一次性凭据绑定模型服务完整配置、目标连接实例及实际文件/目录，5 分钟有效、最多 4 个待用范围；发送时原子消费，重生成也需新的读取授权。模型不能指定其他服务器，原连接失效后不能自动改用重连后的连接。
- 仅提供列目录、查看属性、UTF-8 普通文本有界读取。复用认证 SSH 的专用 SFTP 子通道，不复用交互终端输入，不另建登录；逐组件拒绝符号链接、拒绝 `..`/控制字符/反斜杠、校验规范路径与范围边界，并在打开与返回结果前后核对属性和路径。二进制、非 UTF-8、缺少必要属性及读取期间变化明确失败。
- 默认单次文本 8 KiB、上限 16 KiB；目录默认 50、上限 100 项，偏移最多 1000，不递归；单次查询 10 秒。每次提问最多 4 轮模型、8 次工具、64 KiB 结果及 4 MB 模型正文/思考/工具参数。保留当前服务总超时与全局单运行限制；实际定义、历史和结果均受模型输入预算约束。
- Rig Tool / Agent / Hooks 负责调用、调度和配对；本机负责目标/路径/预算校验、单次范围授权、UI 和持久化。公共事件序号与本次 requestId/messageId/callId 关联，工具真实开始与结果使用 Hook 事件，不把 Rig 批次提交投影视为即时开始。工具状态独立于思考，支持展开详情、截断提示、停止/中断；后续模型轮次的思考仍实时展开，正文返回后收起。
- 完成的原生 Rig 历史保留在回答版本内，取消/失败不进入后续有效历史；摘要切点保留完整用户回合，不能从工具结果中间截开。普通聊天在已知支持工具时仅声明历史定义并设置 `ToolChoice::None` 回放成对协议，不注册执行器；未知/不支持时采用 Rig 内置文本回放，结果仍标为历史数据。服务切换确认明确涵盖工具读取结果，不自动恢复查询权限。
- 数据库 v4 增加工具历史语义，仍沿用消息 JSON 和检查点表；旧 v1–v3 库先一致性备份再升级，旧程序拒绝 v4，防止忽略新字段后重写丢失。退出恢复把未结束工具标为中断；删除消息/对话及回答版本沿用既有关联处理，权限不持久化、不从历史恢复，调用日志不记录正文或工具参数。
- 限制：SFTP v3 不提供原子的 no-follow / chroot / inode 快照，路径/属性前后校验不能替代远程账号权限隔离，也不能声称可抵御恶意服务器或精心构造的并发替换。持续增长日志可能因版本变化拒绝返回；目录分页不是一致性快照。首批验收围绕可信 SSH 服务，强隔离读取须使用服务器侧支持后再扩展。
- 本地验证、真实环境待验收与回退要求见配套迭代计划 M3 交付记录。无命令执行、本地文件工具、附件或图片扩展。
