## 1. 分层与依赖

| 层 | 实现 | 职责 | 后续复用 |
|---|---|---|---|
| SSH 连接 | [Session Supervisor](../../src-tauri/src/session/supervisor.rs) | 获取当前认证连接、校验连接实例，不新建登录，不写交互终端 | SSH Tool 与 Agent 使用同一连接边界 |
| 命令执行器 | [ssh/exec.rs](../../src-tauri/src/ssh/exec.rs) | 独立通道、POSIX 目录包装、stdout/stderr、退出/信号、超时、输出保留和通道清理 | 接收通道、命令、ExecOptions 与报告回调；不依赖 AI、Rig、Pinia 或界面 |
| 执行门禁 | [exec_access.rs](../../src-tauri/src/ai/exec_access.rs) | 单次提议授权、目标实例绑定、具体命令确认、单用许可与失效 | 以 request/message/call/approval 标识关联运行，后续 Agent 复用该门禁 |
| 工具适配 | [tools.rs](../../src-tauri/src/ai/tools.rs) | 注册 Rig Tool、执行前 Hook、配对历史、事件与输入预算 | 后续任务由 Rig 继续调度，复用执行器与确认逻辑 |
| 存储/事件 | [runtime.rs](../../src-tauri/src/ai/runtime.rs)、[storage.rs](../../src-tauri/src/ai/storage.rs) | 关键状态持久化确认、流式转发、取消与崩溃恢复 | 保留实际效果记录，作为后续任务步骤证据 |
| 界面 | [工具设置](../../src/components/ai/AiReadScope.vue)、[工具记录](../../src/components/ai/AiToolSteps.vue) | 使用公共组件选择能力、完整预览命令、确认/拒绝、展示结果 | 可替换为任务界面，不改写底层执行器 |

执行器返回的 `Execution` 定义位于 SSH 层。AI 消息引用该类型，SSH 层不会反向引用 AI 类型。

## 2. 执行契约

- 复用已有认证 SSH 连接，打开专用 session channel；不分配 PTY、不复用活动终端输入，不重连或更换目标。
- 首版明确支持远端 `/bin/sh`。发送 `exec /bin/sh -c <安全引用的脚本>`；有 cwd 时先安全引用绝对路径并执行 cd，失败立即退出，不继续后续脚本。
- cwd 是用户审阅的请求目录，不从终端标题或历史文本推断，也不声称是交互终端的当前目录。代码内部再 cd、容器或远程跳转属于所批准脚本的行为。
- 命令正文最多 8 KiB、用途最多 1 KiB，拒绝 NUL、不可审阅控制字符及方向覆盖字符；参数使用严格 JSON schema 和后端校验。命令允许多行，确认卡片展示完整原文，不通过摘要替代。
- EOF 关闭 stdin，不注入系统密码或 SSH 凭据；sudo、交互程序和后台派生进程不承诺自动处理。
- `ExecOptions` 独立承载超时和保留量；M4 适配层使用默认 30 秒、stdout/stderr 合计 256 KiB。后续任务可在其权限/预算策略内选择参数，执行器不内置“4 轮”“一条命令”等 Agent 限制。
- 保留量达到上限后仍持续读取，记录收到字节数和截断状态；按 UTF-8 显示，非法编码明确标记替换。审计保存最多 256 KiB，模型上下文只接收每流最多 4 KiB、合计最多 8 KiB 的预览，继续受输入预算限制。

## 3. 授权与一次派发

1. 用户在工具设置启用下一次问答的命令提议能力。该凭据 5 分钟有效、单次消费，绑定目标连接及完整模型服务配置；它只允许提出命令。
2. 模型提出 command/cwd/purpose，后端验证参数并生成新 approvalId；确认绑定 requestId、messageId、callId、目标连接、完整命令和目录。
3. 待确认记录落盘后展示完整卡片，最多等待 60 秒，等待计入本次请求总超时；M4 总运行还受服务超时与 5 分钟上限约束。
4. 用户确认只消费一次 pending entry。门禁再次核对运行、取消状态、有效期和原连接。批准记录落盘后才生成一次执行许可，执行器实际收到的参数必须与批准内容相同。
5. 执行器通过报告回调等待“正在派发”记录落盘确认，再从唯一边界发送 SSH exec。存储失败、接收端关闭或取消均不能越过该边界开始执行。
6. 拒绝/过期保留未执行记录，模型可解释结果；本次 M4 最多一条命令提议，不自动更换命令继续审批。重生成或新问答需要新的提议授权与具体确认。

M4 的单条限制属于运行门禁。后续多步骤 Agent 可扩展运行预算和步骤授权；每个执行效果仍通过同一确认与派发边界。

## 4. 状态与取消

| 状态 | 已知事实 |
|---|---|
| waiting_approval | 正在等待具体命令确认，尚未派发 |
| approved | 该命令已批准，尚未派发 |
| running / dispatching | 正在或已提交 exec 请求；崩溃后无法仅凭本地记录确认是否执行 |
| completed / failed + exited | 收到退出码或退出信号，保存输出及其完整性；非零退出不等于工具协议失败 |
| denied / expired / interrupted + not_started | 未获得有效许可或在派发前中断，原确认失效 |
| unknown | 已跨派发边界，超时、停止或断线后未确认远端退出，需要先核实远端状态 |

- 停止不启动后续步骤，取消运行 future，并由通道 guard 尝试 TERM 与关闭；两项请求分别限时，不能因信号请求阻塞而省略关闭请求。
- 关闭一个执行通道不关闭共享 SSH 连接或用户交互终端。TERM/close 不保证服务器已处理，不保证所有后台后代进程结束。
- 流式输出使用合并通知，最多保留一个尚未消费的最新进度快照；不能让慢存储或界面导致无界事件队列。
- 待确认时切换聚焦终端、模型或关闭助手会停止等待；运行后保留原目标绑定。锁屏撤销待用范围和确认，并停止活动运行。

## 5. 审计、恢复与日志

- 关键状态等待数据库确认后才推进；已有周期检查点先排空，防止旧输出快照覆盖新的派发状态。
- 数据库 v5 在从旧版本升级前生成一致性 pre-v5 备份。旧 v4 程序拒绝 v5，不通过手工降低版本号回退。
- 重启将未派发状态置为中断、已派发但无终态置为未知；清空确认标识，不恢复授权或自动重新执行。远端效果不宣称“恰好一次”。
- 完成的调用/结果通过 Rig 保持配对；不启用命令工具时没有执行器。历史回放使用对应 schema 并显式禁止当前调用，或由 Rig 对不支持工具模型投影为历史文本。
- 模型调用日志保留允许的诊断字段，不记录命令、工具参数和输出正文。用户可在本地聊天记录中审阅工具事实。
- 现有命令知识库规则仅作敏感命令提醒；它们位于前端并有匹配范围限制，不构成后端权限判断。所有 Shell 命令仍逐条确认，不展示“通过规则即可安全执行”的结论。

## 6. 后续 Agent 的扩展位置

- 目标、任务步骤、暂停/继续、模型轮数、工具次数和总时长预算放在任务运行层，并继续采用 Rig 调度。
- 任务步骤关联已有执行事实与 callId，先核实未知结果再决定下一步；恢复任务不自动重新派发已批准或未知的命令。
- 图形入口可从当前工具设置合并为任务权限，不要求执行器或结果模型随界面重做。
- 多平台远端 Shell、命令编辑、工作区策略、环境变量和更强的远程进程隔离需要独立契约；当前不通过猜测 OS 或 Shell 静默切换后端。

本地模拟结果见迭代计划 M4 交付记录；不以模拟协议服务代替真实服务器、代理/跳板及原生窗口验收。


## 7. M5 首轮与扩展边界（2026-11-07）

- M5 通过任务模式取得提议能力，复用同一执行器和确认门禁；8/12/4/5 分钟限制位于任务与运行层，执行器仍使用调用方给定的 ExecOptions。
- 当前 Tools 改由 Rig 原生 ToolServer/ToolServerHandle 注册。内置能力正常发布，未知工具默认拒绝；以后接 MCP 需为服务身份、传输和每类能力接入宿主授权策略，不能凭 MCP 的 readOnly 注解或 Skill 文本赋予权限。
- 当前 SSH 能力是应用内 Tool，尚不是对外 MCP 服务。Skill 属于诊断方法、步骤和约束层；MCP 属于外部能力连接协议；插件可封装它们及配置/界面。各层可组合，不互相替代。
- 核对 Rig 0.46 的本地源码：AgentBuilder 支持 dynamic_tool(s) 与 tool_server_handle，原生注册器支持运行时注册；当前 core/agent 集成可以在此边界扩展。
- Rig 完整 Harness/编码 Agent 体系另有插件装配、SkillsPlugin 与 MCP 插件，不能把当前 core/agent 依赖误记为已经集成插件管理。参考：[官方迁移说明](https://docs.rs/crate/rig/latest/source/MIGRATING.md)、[MCP 插件文档](https://docs.rs/rig-mcp-client/latest/rig_mcp_client/)、[0.46 发布说明](https://github.com/0xPlaygrounds/rig/releases)。实施时继续按精确版本源码核对，不照搬 main 分支的新 API。
- 本轮未新增 Harness/MCP/Skill 依赖，也未做插件市场、自动安装或外部 MCP 服务管理；这些按后续范围独立评估，优先使用 Rig 现有模块，避免重复维护加载/连接体系。
