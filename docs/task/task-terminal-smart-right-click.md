## 背景与目标

### 当前问题

- 终端区域右键始终打开现有菜单；即使 xterm 中已有文本选区，用户仍需在菜单中再次选择“复制”。
- 用户希望有文本选区时右键完成复制并将选区安全粘贴到当前输入；无选区时保留现有菜单，同时避免粘贴换行触发命令执行。

### 期望结果

- 提供全局、可持久化的终端右键行为设置。
- 推荐的“智能复制粘贴”模式下：有文本选区时右键复制选区并安全粘贴同一文本；无选区时显示当前完整右键菜单。
- 保留“始终显示菜单”模式，供偏好当前行为的用户选择。
- 设定变更后，已打开的终端及分屏终端无需重连即可应用新行为。

## 关键规则与边界

- “智能复制粘贴”是推荐默认模式：有非空选区时，阻止菜单触发、复制选区，并将过滤后的同一文本粘贴到当前终端；无选区时不拦截事件，显示现有菜单。
- “始终显示菜单”保持当前行为，是对既有用户习惯的兼容选项。
- 选区判断必须绑定当前 `Terminal.vue` 实例，不能读取其他分屏的状态。
- 右键事件需要在菜单触发器打开前拦截；有选区时不得同时出现复制成功提示和右键菜单。
- 智能粘贴须将 `U+0000`–`U+001F`、`U+007F`–`U+009F` 以及 Unicode 行/段分隔符替换为空格，保证选区中的 Enter、Tab、Esc、Ctrl+C 等控制内容不会触发执行。
- 剪贴板写入失败时不得继续粘贴，并显示错误提示；不得将剪贴板内容写入日志。
- 菜单关闭后的终端重新聚焦行为保持不变；智能粘贴只发送过滤后的选区文本。
- 串口终端复用同一组件时遵循相同语义，不改变串口专属菜单条目。
